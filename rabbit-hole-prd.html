What Rabbit-Hole Is

Rabbit-Hole is not a monitoring dashboard. It's a legibility layer — it makes AI agent decision-making transparent, searchable, and auditable by both humans and other agents.

🔬 Kernel-Level Truth

Attaches via eBPF directly to the agent process. Every syscall, network request, file operation, and LLM API call is captured at the kernel level. The agent cannot lie about what it did — the kernel saw everything.

🧠 Local Classification

A local Gemma model turns raw syscall traces into semantic understanding: "read auth.go (247 lines, 2ms), decided to patch middleware.go, wrote 12 lines." Runs on-device. No cloud, no API keys, no privacy leak.

💬 Chat Interface

Ask natural language questions: "What did helios do at 3am?" "Show me the context window when it decided to patch middleware.go." "Is dexdat getting slower?" Humans and agents both query Rabbit-Hole.

🔄 Agent-Supervises-Agent

Supervisor agents query Rabbit-Hole's REST API to debug worker agents. Fleet operators automate compliance and anomaly detection. The ultimate use case: agents debugging agents.

📦 One Binary, Zero SDK

Works with closed-source CLI agents. No SDK to install, no library to link. Attach by PID. The kernel doesn't care if the binary is open-source or proprietary.

🏠 Self-Hosted First

Single Go binary with embedded SQLite. No external dependencies beyond a Linux kernel ≥ 5.8. Data never leaves the machine. Install in 60 seconds.

Each Layer, In Detail

The three layers are independent, replaceable, and communicate through well-defined interfaces.

🔍 COLLECT — Kernel Telemetry

eBPF programs attach to tracepoints and uprobes on the agent process. Raw syscall events stream into a ring buffer. Zero SDK — works with closed-source binaries. The kernel captures: every openat, read, write, connect, execve; TLS-encrypted LLM API calls (via uprobes on libssl); file operations with filenames and byte counts; CPU/memory per process; optional context windows at decision points.

🧠 CLASSIFY — Semantic Understanding

Two-pass classification. First pass: fast pattern matching catches 80% of operations (file reads, writes, network connects) with 95%+ confidence. Second pass: local Gemma 3 4B model classifies complex patterns the matcher can't resolve. Output: intent (read_file, write_file, api_call, exec_command...), phase (observation, deliberation, action, verification), outcome (success, failure, timeout), confidence (0.0–1.0), human-readable description. Runs entirely on-device. No cloud dependency.

💬 EXPRESS — Natural Language Query

Chat is the primary interface. Natural language questions are translated to structured searches, executed against the flow store, and synthesized into natural language answers with context. Plus: structured REST API for agent-to-agent queries, WebSocket for real-time flow streaming, search across all sessions with FTS5 full-text search, context window retrieval — see exactly what the agent saw at each decision point.

🗄️ STORAGE — SQLite with FTS5

Single SQLite database in WAL mode. Full-text search via FTS5. Automatic retention policies (default 30 days). JSON columns for flexible metadata. Schema versioned with migrations. Zero external dependencies — the database file is portable.

Competitive Landscape

Existing tools address pieces of the problem. Nobody does the full stack — especially the classification layer and chat interface.

AgentSight
Academic research — eBPF + TLS interception
Does Layer 1 (collect). No classification pass. No chat interface. No context window retrieval. Academic prototype, not a product.
AgentOps / LangSmith
Commercial — Python SDK, 400+ framework integrations
SDK-dependent. Cannot work with closed-source agents. Dashboards, not chat. No system-level telemetry. Commercial with per-trace pricing.
Arize Phoenix
Open Source — OpenTelemetry, span replay
SDK-dependent. Span-level, not syscall-level. No classification pass. Span replay requires instrumentation. No chat interface.
groundcover
Commercial — eBPF for Kubernetes
Kubernetes-only. Enterprise pricing. Designed for infrastructure monitoring, not agent debugging. No classification or chat layer.

🪤 The Rabbit-Hole Gap

Nobody does the classification layer — turning raw syscall traces into semantic understanding.
Nobody uses chat as the primary interface for agent debugging.
Nobody does context window retrieval at decision points.
Nobody designed for agent-supervising-agent — where one AI queries another's trace history.
Nobody ships as a single self-hosted binary with zero SDK requirements.

Quickstart (Target)

The goal: external dev goes from zero to working harness in under 5 minutes.

# 1. Install
curl -sSL https://gitlab.readydedis.com/rabbit-hole/rabbit-hole/-/releases/latest/downloads/install.sh | bash

# 2. Start daemon
rabbit-hole serve

# 3. Attach to your agent
rabbit-hole attach --pid $(pgrep hermes)

# 4. Ask questions
rabbit-hole chat "What did my agent do in the last hour?"

# 5. Or from a supervisor agent
curl -s localhost:9734/api/v1/chat -d '{"message":"Show me all failures since midnight"}'

🐇 Go down the rabbit hole.

rabbit-hole attach --pid <PID>
